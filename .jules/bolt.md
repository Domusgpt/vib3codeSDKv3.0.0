## 2024-06-27 - [Closure Allocation Overhead in Holographic Rendering Paths]
**Learning:** In the `QuantumEngine` and `RealHolographicSystem`, render frames are executed continuously via `requestAnimationFrame` at ~60fps. Iterating over the active `visualizers` array inside these render loops using `this.visualizers.forEach(visualizer => { ... })` allocates an anonymous closure function on every single frame. When the application scales to complex scenes with multiple visualizers (like a 5-layer holographic bridge), this triggers substantial micro-allocations, leading to excessive Garbage Collection (GC) pressure and observable frame stutter.
**Action:** Always replace `.forEach` array methods with traditional, length-cached `for` loops (e.g. `for (let i = 0, len = this.visualizers.length; i < len; i++) { ... }`) inside the core render or animation loops (like `_renderDirectFrame`, `render`, `startRenderLoop`). This eliminates the per-frame function allocation entirely, preserving a smooth 60fps experience under heavy load.
